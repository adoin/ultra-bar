# Ultra Bar

Rust 编写的 Windows 10/11 自建任务栏技术原型。原生 Win32/GDI 负责窗口和绘制，Rune 负责插件脚本及其 UI 内容。

## 诊断日志

- 安装版统一写入 `ultra-bar.exe` 所在安装目录的 `logs`；开发运行副本统一写入本项目 `target/logs`。主程序、插件、恢复进程共用根目录。
- 按本机日期分目录，只保留最近 **7 个有日志产生的日期**，不是“当前日期减 7 天”，同一天重启多次也只算一天。例如只在 1、5、9 号运行，累计为 3 个活跃日期。新活跃日期产生时清理更早的受管日期目录，不清理无标记的其他目录。
- JSONL 文件按维度和进程分开，记录本机时间、UTC 毫秒、单调时钟、PID/TID、运行批次、来源及事件。维度包含生命周期／崩溃恢复、系统任务栏接管、托盘快照与查询失败、固定项增删和顺序、窗口操作、插件启动退出和标准错误、配置变更、搜索、用量、日历、渲染环境及每分钟资源健康快照。
- 固定项日志包含操作原因、增删目标和前后顺序；配置目录文件事件可记录外部修改造成的前后差异，但普通文件通知无法识别外部编辑器的进程身份。
- 不主动记录搜索词、聊天或日程正文；凭据字段和常见授权头脱敏。设置保存日志记录字段数量、版本及结果，密码不会作为设置值写日志。异常日志记录代码、地址及相对启动时钟；恢复进程另记主进程退出码，覆盖部分无法正常执行日志清理的崩溃。
- 后台有界队列写入，单条最多 16 KiB、单文件约 8 MiB 分卷；队列拥塞时记录丢弃数量。没有逐帧写盘或新增网络轮询。运行 `ultra-bar.exe --log-smoke D:/tmp/<独立任务目录>` 可隔离验证活跃日期保留、并发写入和脱敏，不接管任务栏。

## 开发

需要 Windows 10/11、PowerShell 7、Rust MSVC 工具链及 Visual Studio C++ Build Tools。

```powershell
pwsh.exe -NoLogo -NoProfile -File ./dev.ps1
```

这条命令可直接填入项目环境的启动命令。自动发现同级 `../ultra-bar-plugins`；可用 `-Plugins D:/path/to/plugins` 指定插件仓库。

- 默认 Cargo 单任务、2 个逻辑处理器、BelowNormal 优先级、Windows Job Object 全机 20% CPU 硬上限，作用于开发进程树，包括 rustc 和链接器。启动失败会报错，不会回退到无限制编译。
- CPU 上限是 Windows 调度约束，短时采样可能有波动；不代表内存和磁盘 I/O 同时受限。首次 Rune 编译仍可能耗时。
- Rust / Cargo 配置保存后，文件事件经过防抖，串行构建。旧窗口继续运行，构建成功后才关闭、复制并启动新程序；失败时保留旧程序。
- Rune / plugin.json 保存后由宿主后台线程重载，不触发 Cargo，不重启任务栏。脚本错误保留上一份可运行插件，删除插件目录则卸载。
- 新版 dev runner 会同时监听插件仓库的 Rust 源码；原生插件按同样的 jobs/CPU 限制串行构建，成功后发布到插件 `.runtime/` 的版本目录。更新 `dev.ps1` 后需要重新启动开发 runner 才能使用新增的监听目录。
- 不创建全局配置、不设置开机启动。诊断日志位于 `target/logs`，控制台实时输出仍可在 `target/dev-watch/app.err.log` 查看；构建缓存位于 `target/dev-build`，运行副本位于 `target/dev-run`。
- 同时只允许一个开发 runner 和一个任务栏实例。Ctrl+C 清理本 runner 启动的进程，不按程序名称结束其他项目。

```powershell
# 可调整；建议先保留默认值
pwsh.exe -NoLogo -NoProfile -File ./dev.ps1 -Jobs 1 -CpuPercent 15 -BuildCores 2
# 相同资源限制下执行检查、测试或 Clippy
pwsh.exe -NoLogo -NoProfile -File ./dev.ps1 -Task Check
pwsh.exe -NoLogo -NoProfile -File ./dev.ps1 -Task Test
pwsh.exe -NoLogo -NoProfile -File ./dev.ps1 -Task Clippy
# 只构建并暂存原生插件，不启动另一个任务栏实例
pwsh.exe -NoLogo -NoProfile -File ./dev.ps1 -Task PluginBuild
# 构建后运行 8 秒并退出，便于项目环境验证
pwsh.exe -NoLogo -NoProfile -File ./dev.ps1 -SmokeTestSeconds 8
```

`.cargo/config.toml` 也默认 `jobs=1`，但直接调用 Cargo 不会自动获得 Job Object 的 CPU 硬上限，日常开发请使用 `dev.ps1`。

## 当前行为

启动默认接管：自动隐藏原生任务栏，由 Ultra Bar 占用主屏底部，并通过 AppBar 为最大化窗口预留空间。直接运行可执行程序与 `dev.ps1` 行为一致。

开始按钮显示像素对齐的四格 Windows 标志，左键打开当前系统原生开始菜单（Ctrl+Esc），右键打开原生 Win+X 菜单。通知入口使用系统图标，按系统版本发送 Win10 的 Win+A 或 Win11 的 Win+N。时钟保留日期和时间数字，旁边使用日历图标，点击打开日期和时间设置。应用按钮显示应用图标，长标题使用省略号，悬停显示完整标题；支持基本窗口切换、恢复和最小化。右键栏内非开始区域可退出。

全栏使用 Windows 合成器背景模糊及逐像素透明表面，文字和图标保持不透明。鼠标悬停才更新按钮高亮，不运行持续动画或截图采样。Windows 10 的背景模糊使用运行时解析的 `SetWindowCompositionAttribute` Accent 接口，其兼容性依赖系统版本；接口不可用时回退为实色表面。实际毛玻璃效果仍需在本机确认。

`Clicks` 是验证插件事件的示例计数器，现保留于插件仓库 `examples/counter`，默认不加载。

应用区按剩余宽度自动切换三档：

1. 空间足够时显示图标和标题，长标题省略、悬停查看全称。
2. 标题放不下时全部切换为仅图标。
3. 图标也放不下时，围绕当前应用保留连续的一段，两端分别出现收纳入口；点击入口可选择被收纳的应用，选中后会进入可见区域，不改变原有顺序。

所有档位均可拖拽应用图标排序。拖到其他图标的中线后交换位置；拖至两端收纳入口并停留，会继续向该方向移动，允许跨收纳区排序。拖拽不会触发应用切换，窗口关闭或新开时保留其他窗口的手动顺序。顺序在当前宿主进程内保留。

右键任务栏的非开始区域，选择 **设置 → 始终仅图标**，可持续使用纯图标布局；选择 **自动显示标题** 恢复三档自适应。设置保存在 `%LOCALAPPDATA%/UltraBar/settings.json`，重启程序及开发热重载后仍生效。图标空间不足时，两种设置都会使用两端收纳。

**设置 → 任务栏大小 → 正常／小** 可即时切换尺寸。以 96 DPI 为基准，正常栏高 40、应用图标 32；小栏高 30、应用图标 16。开始按钮、字体、图标间距及底部 AppBar 占位同步调整，并随系统 DPI 缩放。尺寸选择会持久保存，与“始终仅图标”设置互不影响。Windows 标志使用等宽直边方格和整数像素间隙，避免小尺寸斜边的台阶感。

Windows 标志直接在最终物理像素表面绘制，避免缩放插值；应用优先取得大图标及对应 DPI 的可执行文件图标，并按实际尺寸绘制，不再将小图标放大至任意尺寸。图标缓存在窗口存续期间，切换窗口和更改标题不会重新读取图标；DPI 改变时才刷新尺寸。

**设置 → 时间格式** 提供预设和自定义格式，例如 `MM-DD HH:mm`、`YYYY-MM-DD ddd HH:mm:ss`。支持 `YYYY/YY` 年、`MM/M` 月、`DD/D` 日、`HH/H` 24 小时、`hh/h` 12 小时、`mm/m` 分、`ss/s` 秒、`ddd/dddd` 星期、`A` 上下午；`[]` 内为固定文字。只改变本程序的时钟显示。时钟按实际内容测量宽度，避免固定宽度留下空白。

时钟区是 API v2 的扩展槽，插件可以替换显示内容、图标和点击行为。**设置 → 时钟扩展** 可选择自动、系统入口或已安装的时钟插件。默认安装的 `schedule-calendar` 显示配置后的时间，点击整块区域展开／收起日历。原生面板在独立进程中运行，随任务栏退出；UI 绘制依旧按事件触发。

Schedule Calendar 的功能、数据位置和迁移来源见 [插件说明](../ultra-bar-plugins/schedule-calendar/README.md)。日程数据独立保存在 `%LOCALAPPDATA%/UltraBar/plugins/schedule-calendar/calendar.json`。

**设置 → 插件中心** 管理官方源和自定义 GitHub 仓库，各仓库用 tabs 区分。默认官方源为 `adoin/ultra-bar-plugins`，目录来自 Releases；日历稳定 ID 为 `com.emssion.schedule-calendar`。发布包使用 `.ubplugin` 后缀，程序支持当前用户文件关联和独立强制安装，同版本覆盖／降级仍执行包校验。安装后按 ID 通知宿主重载，不改写插件数据。完整协议及 tag 发布方式见 [插件生态说明](docs/plugin-ecosystem.md)。

右下角的上箭头展开系统托盘，面板只保留图标和必要的翻页入口；悬停显示图标原有提示，支持向 Explorer 托盘转发左键、双击和右键操作。图标操作是原生工具栏桥接，不是按可执行文件路径重新启动程序，也不使用全局键鼠输入。

右侧托盘与左侧任务栏分开计算密度：常驻托盘、系统入口和时钟每侧留 3 个逻辑像素，item 之间仍为 2 个物理像素；收纳面板使用 30 个逻辑像素的格子加 2px 间隔。无法复制原生托盘 HICON 时回退到应用资源图标，保留入口和原有操作。版本 4 的右键按系统 `WM_CONTEXTMENU` 通知打包屏幕锚点与 ID，旧版沿用 Explorer 工具栏转发；发送前复核图标身份和所属进程。

Win10 托盘图标通过 Explorer 的 `ITrayNotifyWin8` 只读通知订阅实时同步：收到图标变化后立即复制本次图像，保留发送者头像及透明帧，跟随软件自己的闪烁与恢复行为。动态图像优先于静态程序图标回退，图像相同的事件不重复绘制；逐帧更新不扫描全部托盘、不写入显示偏好。常驻区与已展开的收纳面板使用同一份图像快照，头像变化不会重新定位面板。不使用会独占旧式回调的 Win7 接口；订阅不可用时继续使用原有事件桥接，Explorer 重启后重新连接。此私有接口已在本机 Win10 验证，其他系统版本仍需实测。

右键任务栏 → **设置 → 导入系统托盘设置**，读取 Windows 当前的常驻／收纳结果，合并到 `%LOCALAPPDATA%/UltraBar/tray.json`。不修改 Windows 设置，不覆盖 Ultra Bar 已有的选择。初始化时若没有数据，仅提示导入一次；选择“否”跳过，重启和热重载后都不会再提示，仍可随时从设置手动导入。**设置 → 托盘图标** 可逐项选择“显示在任务栏”或“收纳到托盘”；新发现的图标默认收纳。常驻区空间不足时，其余图标仍可从面板访问。离线程序保留偏好，未运行的程序不会通过配置文件被启动。

当前原生操作桥接针对 x64 Win10 的 Explorer 工具栏实现；使用原生按钮转发，保留 Explorer 对不同回调版本的处理。数据格式不兼容或没有读取权限的图标不会伪造入口，其余可用图标继续显示。Win11 的新版托盘需要独立验证；其具有明确应用路径和 UID 的注册表偏好可被导入，但这不代表图标操作已兼容。具有相同可执行文件路径和 UID 的多个实例共享显示偏好，各运行图标保留独立操作目标。

托盘读取在后台线程中进行，系统事件触发更新，没有持续扫描循环。查询有超时和身份复核；超时后暂停本进程对该 Explorer 实例的桥接，可重启 Ultra Bar 重新尝试，无需强制重启 Explorer。只读诊断命令（不触发鼠标或键盘，不导入设置）：

```powershell
pwsh.exe -NoLogo -NoProfile -File ./dev.ps1 -Task TrayDiagnose
```

需要保留原生任务栏时使用预览模式，在原生栏上方显示自建栏，不改变工作区：

```powershell
pwsh.exe -NoLogo -NoProfile -File ./dev.ps1 -Preview
# 直接运行可执行程序时使用 --preview；原有 -Takeover / --takeover 仍兼容。
```

接管模式暂时将原生任务栏设为自动隐藏、隐藏原生窗口，并注册底部 AppBar。退出时恢复原生任务栏和原来的自动隐藏设置；独立恢复进程等待宿主退出，负责宿主异常结束后的恢复。恢复进程只等待进程句柄，不做循环轮询。恢复不依赖开发 runner 存活。

固定应用首次启动会自动导入系统任务栏的快捷方式；也可拖入 `.lnk` / `.exe` 或右键运行中的应用固定。快捷方式副本与顺序保存在用户数据目录，保留启动参数、工作目录及自定义图标；任务栏提取原始图标资源，不显示快捷方式覆盖箭头。应用按完整 EXE 路径分组，固定项启动后复用原栏位，多窗口选择和两端收纳列表使用跟随主色的圆角毛玻璃面板，支持完整标题提示、滚轮和键盘选择；窗口条目右侧可正常关闭对应窗口，并保留应用的保存确认；拖动固定项会保存顺序。正在运行的栏位使用完整圆角衬底和阴影，前台应用进一步加亮；收到 Shell 闪烁请求时显示暖色提醒，激活后清除，不读取聊天消息。系统固定顺序从 Taskband 中匹配文件名尽力恢复，不修改原生固定数据；打包应用和不同启动器之间的 AppUserModelID 分组仍待完善。

拖入 `.exe` 或 `.lnk` 会直接固定应用，不需要文件选择菜单。拖入 `.ps1`、`.cmd`、`.bat`、Python 或 Windows Script Host 脚本时，入口统一归入“脚本”图标；脚本快捷方式保留原参数及工作目录。左键或右键展开脚本列表，最多显示 8 行，可用滚轮、方向键、Home/End 浏览。拖入不会执行文件，点击某一项才启动对应运行环境；脚本控制台独立于任务栏和开发进程，任务栏重启不会终止已启动脚本。脚本列表保存在 `taskbar-scripts.json`，原文件留在原位置。

托盘图标可从收纳面板拖到任务栏右侧常驻区，也可从常驻区拖回面板（拖动时自动展开），或拖到收纳入口。显示选择写入本地托盘设置；没有本地选择时沿用原生显示/隐藏状态。拖动和取消不会转发为应用点击。

这是单主屏技术原型，托盘桥接仍需逐程序验证。尚未完整实现原生日历、独立的音量/网络/输入法区域、窗口缩略图预览/Jump List、多屏布局及 Explorer 重启后的持续接管。需要使用未兼容的原生托盘入口时可退出 Ultra Bar 或使用预览模式。Win11 需要独立测试。

任务图标右键菜单使用主色毛玻璃面板，按任务栏上下可用空间限制高度并置顶；不重复显示当前窗口标题和底部分页计数。窗口关闭查询 `GetSystemMenu` 中 `SC_CLOSE` 的存在及启用状态，再发送 `WM_SYSCOMMAND/SC_CLOSE`，保留应用的保存确认；系统关闭缺失或禁用时不绕过限制。

右键菜单按 Windows AppUserModelID 接入 Jump List。最近/常用使用 `IApplicationDocumentLists`，自定义任务、分类和固定项通过受版本接口查询保护的 Shell 兼容层读取；应用发布任务的标准接口为 `ICustomDestinationList`。主程序只读取现有列表，不改写第三方应用列表。读取运行在独立进程，启动前分配单核、BelowNormal、20% CPU 硬上限与随父进程关闭的 Job，2.5 秒超时；菜单先显示基础操作，异步补充条目，短缓存 5 秒、最多 8 个应用上下文，没有持续轮询。原始 ShellLink/PIDL 保存在临时查询缓存中，点击时交由 Shell 执行，保留参数、工作目录及 Shell 目标。已在本机 Win10 验证 Chrome 自定义任务及资源管理器固定/最近项目；未公开接口在未知 Windows 版本上可回退为可读取内容和基础操作，Win11 仍需实机验证。

任务栏横向 item 外边界之间固定相隔 2 个物理像素，不随 DPI 放大。内容左右 padding 独立计算：正常尺寸每侧 8、小尺寸每侧 6 个逻辑像素，随 DPI 缩放；绘制、点击及拖动锚点使用相同尺寸。

应用组有多个窗口时，在图标右上角显示主色数字角标，单窗口和未运行的固定项不显示；100 个及以上显示 `99+`。正常／小号模式分别调整尺寸，角标跟随图标一起拖动，点击仍打开原有多窗口选择面板。

拖拽排序时，图标跟随指针，相邻项通过独立的 DirectComposition 图层用约 140ms 缓动让位，插入判断使用稳定的逻辑槽位。正常、小号、带标题与两端收纳拖动共用排序逻辑；松手后保存固定项顺序，取消或失去捕获会恢复原顺序。归位完成后释放动画图层，没有常驻动画帧计时器；既有边缘收纳检测只在拖动期间工作。`ultra-bar.exe --taskbar-smoke D:/tmp/<任务目录> --drag-smoke` 使用隔离 profile 验证让位、归位、取消及两端收纳，不发送全局键鼠输入。

使用官方 Godot 宿主运行的开发游戏，按窗口发布的项目 AppUserModelID 分组，避免并入通用 Godot Engine 固定项；编辑器仍沿用原固定项。游戏使用自身窗口标题和图标，同项目的多个实例共享游戏栏位。身份查询在后台按窗口／进程缓存，不在任务栏 UI 线程进行 Shell COM 查询，也不修改游戏窗口或项目配置。

## 性能边界

主色可在“设置 → 主色…”中选择或输入 HEX，保存到 `settings.json` 的 `accent_color`。共享 SDK 以 HSL 生成任务栏、插件中心、托盘面板、日历及编辑器的衍生色；任务栏采用统一左上光源：非激活运行项为浮起外阴影，激活项为凹陷内阴影，不绘制亮色边框。阴影沿用主色 H，S 降至主色饱和度的约 12%–18%，L 相对背景推导明暗，避免发光描边。材质栅格按尺寸、DPI、状态及主色缓存，保留逐像素透明度，图标与文字独立保持清晰。颜色确认后即时通知已打开的插件窗口，取消不修改主题。颜色选择器只在交互时重绘，没有动画循环。

窗口使用阻塞消息循环，只有失效时双缓冲绘制，没有持续帧循环。1 秒计时器检查日期/时间、前台应用、已合并的窗口变化和冒烟退出时间；内容没有变化就不触发绘制。窗口枚举由系统事件置脏后触发，最多每秒一次。只有拖拽期间才启动 150 毫秒边缘检测计时器，收纳区移动间隔至少 400 毫秒；释放鼠标或失去捕获即停止。

插件文件使用系统文件事件监听，350 毫秒防抖，在单个后台线程串行编译。插件只在载入、更新、点击时执行，不逐帧运行；每次执行有 VM 指令预算，文件大小、插件数量、输出长度和宽度均有限制。只暴露列举的系统动作，不提供任意进程执行或文件系统 API。它仍是早期插件 API，不应把进程内 VM 当作运行不可信原生代码的安全边界。

插件契约和示例见同级仓库 `ultra-bar-plugins/README.md`。

自绘文字统一使用共享 Native UI SDK 的 DirectWrite／Direct2D 灰度抗锯齿，半透明表面保留字形边缘覆盖率，后绘阴影不覆盖文字。字体格式和渲染目标按 UI 线程复用；仅在窗口重绘时执行，不添加文字刷新计时器。原生输入框使用系统自然字宽字体平滑。离屏验证入口为 `ultra-bar.exe --text-render-smoke D:/tmp/<任务目录>`，覆盖 96／120／144／192 DPI；每组上行为 GDI、下行为 DirectWrite，以便对比。

Agent 用量气泡使用 DirectComposition 的 DWM 硬件时间轴循环上浮，不依赖应用帧计时器或持续 GDI 重绘。纹理和文字在数据／布局／主题变化时更新，相同场景不再上传或 Commit；窗口隐藏时随宿主隐藏，插件消失时移除合成节点。0%、100%、未知值保持静态，硬件不可用时回退静态材质。

资源管理器及文件夹任务的右键菜单固定提供“此电脑”，打开 Windows 自带的此电脑位置。新增 Everything Search 搜索入口和托盘 Agent Usage 额度条；后台服务、资源上限与协议见 [docs/plugin-services.md](docs/plugin-services.md)。Everything 复用本机现有索引；额度条当前支持 Codex／Claude Code，未知额度显示 `—`。

Windows 正式发行使用 Inno Setup 安装包：`pwsh.exe -NoLogo -NoProfile -File ./scripts/package.ps1`。安装器负责当前用户注册、`.ubplugin` 文件关联、快捷方式、升级退出及卸载；设置与插件数据在卸载后保留。构建和隔离验证说明见 [docs/installation.md](docs/installation.md)。

插件的可编辑内容统一由主程序编辑器服务渲染，插件仅声明字段类型、数据、约束和业务校验；展示视图仍可自定义。接口与维护边界见 [docs/plugin-editors.md](docs/plugin-editors.md)。

用量胶囊按内部可填充区域的面积比例显示余量，先按完整圆角轮廓计算面积，再查表取得横向刻度。每种尺寸缓存 0～100% 共 101 个刻度，小数百分比插值；尺寸或 DPI 改变时按新尺寸建立缓存。背景与 GPU 泡泡使用相同的完整胶囊裁剪，动画不逐帧计算面积。
