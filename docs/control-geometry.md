# 控件几何与命中区域

窗口布局与裁剪不能分别保存创建时的尺寸。`crates/native-ui/src/geometry.rs` 统一维护窗口区域：从实际 HWND 读取宽、高及 DPI，使用同一圆角参数供边框绘制和窗口命中使用。业务窗口只调用 `geometry::attach_rounded(hwnd, logical_corner)`，不得自行固定窗口区域。

## 本次审计

| 问题 | 原因 | 处理 |
| --- | --- | --- |
| 下拉框只有左侧可点 | 创建时裁剪区域约 200px，布局后控件为 480px | 共享几何层随原生窗口尺寸更新区域 |
| 日期、时间及其他圆角窗口存在相同风险 | 多个调用方单独保存窗口区域 | 主程序、共享表单、插件面板及日历窗口共 14 处迁移到共享层 |
| 输入框尺寸缓存不覆盖 DPI 和外部覆盖 | 缓存只有宽高，且与其他区域设置重复 | 删除独立缓存；共享层包含尺寸、DPI 和圆角参数，并校验实际区域 |
| 重复挂载的搜索输入不更新尺寸 | 同会话直接跳过挂载请求 | 同会话原地更新位置和尺寸，保留 HWND、文本及撤销历史 |

窗口销毁时移除子类与状态；重入时不重复设置。只有尺寸、字体、DPI、样式、主题及显隐等窗口消息触发同步，不增加绘制或轮询定时器。区域相同时不重新应用。

## 验证

- 原生 EDIT、COMBOBOX、日期控件覆盖极窄、缩小和扩大、显隐、字体变动、圆角变动及区域被覆盖后的恢复。
- 96、120、144、192 DPI 的几何与圆角组合验证中心、右侧和边缘命中，不把程序调用 `CB_SHOWDROPDOWN` 成功作为点击区域正确的依据。
- 宿主编辑器验证整个下拉输入区域、原生箭头区域与重复展开。
- 挂载更新验证不重建输入框、不覆盖文本、不破坏撤销历史；不同字段或类型需要新会话。

画布内部的进度裁剪、图表遮罩等 HRGN 不属于窗口输入区域，继续由各展示组件管理。
